# Solmare Coast 畫面質感：中／高兩檔畫質

日期：2026-10-03。前置：`2026-10-01-solmare-coast-design.md`（第 1–4 期已合併，本案取代其第 5 期的「效能調校」部分）。

## 1. 目標與成功標準

使用者決定（2026-10-03）：原目標是優化畫面；畫質只做兩檔，**中 = 現在的版本**，**高 = 優化版**；兩檔的差別包含材質與模型的精緻度。

- 高檔畫面明顯不再陽春：地面與路邊、光影、植被與小物件、車子四塊各自以中／高並列截圖驗收。
- 中檔與現在的版本相同：同樣的物件、材質、陰影、後製，效能與 Vision 結果不變。
- 車載相機看到的世界和使用者看到的一致：兩者渲染同一個 scene，所以選中檔時相機看到中檔的世界，選高檔時看到高檔的世界。車載相機不套後製（現況），所以一致的是世界，不是像素。
- 舊地圖（Skyline City、Small town、Interstate 08）與 `lap=1` 的行為和分數不變；所有改動只在 `world.type === "coast"` 下生效。

## 2. 範圍

做：畫質切換與效能量測（第 0 項），以及高檔的 A 地面與路邊、B 光影、C 植被與小物件、D 車子。

不做：
- 低檔、逐項自訂、自訂檔。
- 改動中檔的任何內容（中檔即現況，只有在修 bug 時才動，且要另開 issue）。
- 交通與行人密度（#22 照原 issue 做）。
- 號誌的燈色、燈形、號誌頭數量（AGENTS.md：不為感知改世界；#30 撤回既有改動）。高檔可以提升號誌桿與燈殼的材質，燈色與燈形不變。
- 地圖路網與版圖。

## 3. 現況（2026-10-03 讀碼與截圖）

- 沒有畫質設定；`post.js`（HDR + bloom + 調色）全開，陰影相機半寬 130 m（`sky.js` 的 `SHADOW_HALF`）。
- 沒有主畫面 fps 量測；右下角的 FPS 是車載相機小窗的更新率（`semif-layer.js` 的 `pipFpsText`）。
- 車載相機用同一顆 renderer、同一個 scene 畫進自己的 render target（`semif-layer.js` 約 1233 行），看得到所有物件與共用的陰影貼圖，但不經過 `post.js`。
- 截圖（`docs/visual/new-ui/after-engaged.jpg`）上最陽春的地方：人行道整片無紋理白色且無路緣石；路外是均勻土黃；丘陵光禿；棕櫚是直圓柱加平板葉；葡萄園像綠色方塊；帳篷是純白錐體；路燈粗大；車子缺反射、接縫與接地陰影；整體缺環境遮蔽，物件浮在地上。
- 已有的 CC0 貼圖（`web/textures/`）：asphalt、pavement、grass、dry、sand、rock、bark、brick、`daylight.hdr`。

## 4. 畫質切換（第 0 項）

### 4.1 兩檔的定義

| | 中 | 高 |
|---|---|---|
| 世界（物件、模型、材質、貼圖） | 現況 | A–D 的優化版 |
| 陰影 | 現況 | 可提高解析度與柔邊（B） |
| 後製（主畫面） | 現況 | 可加 SSAO 等（B） |
| 目標設備 | 1080p 內顯筆電 ≥ 30 fps（第 0 項量測確認） | 中階以上獨顯 |

- 實作上以一個 `quality` 值（`"medium" | "high"`）傳進 `semif-world/` 的各個 builder；`"medium"` 走現在的程式路徑，`"high"` 走新的路徑。高檔的新程式放在各模組內的分支或新檔，不改動中檔路徑的輸出。
- 舊地圖不讀 `quality`。

### 4.2 選擇與切換

- 第一次開啟：依 `WEBGL_debug_renderer_info` 的 GPU 名稱初選；名稱含 Intel／UHD／Iris／Radeon Graphics（內顯）／Adreno／Mali／Apple GPU 等字樣，或拿不到名稱時選中，其餘選高。
- 執行中：高檔下主畫面 fps 連續 5 秒低於 27 時，提示一次「畫面不順，可改為中」，**不自動切換**（切換要重建世界，自動切會讓畫面跳動）。
- 設定存在 `localStorage`（讀寫包 try/catch，失敗就用初選）；網址參數 `?gfx=medium|high` 優先，供截圖與評估重現。
- 入口：底部控制列的齒輪圖示，開 Solmare 風格的小面板（兩個選項＋一行說明＋「顯示 FPS」開關），可用鍵盤操作。
- 切換時重建 coast 世界（模型與材質不同），顯示「套用中」；自駕中切換先暫停自駕再重建。

### 4.3 Vision 與評估

- 兩檔的車載畫面不同，Vision 的結果可能不同。所有閉環評估都要標明畫質，用 `?gfx=` 固定。
- 中檔即現況，既有的評估數字（#28）維持有效，作為基準。
- 高檔要另跑驗收 seed，和中檔並列回報發生率（例如「中：闖紅燈 x/30；高：y/30」）。高檔退步時修感知，不把高檔世界改回去（AGENTS.md）。
- 這個邊界寫進 README 與每個 PR：「Vision 的數字以中檔量測；高檔另列」。

### 4.4 效能量測

- 新增主畫面的每幀時間量測；有 `EXT_disjoint_timer_query_webgl2` 時同時量 GPU 時間，主畫面與車載相機分開記。
- 基準跑法：固定 seed 與起點（Solmare Festival），1920×1080，自駕 60 秒，記錄 p50／p5 fps、GPU 毫秒 p50、draw call 與三角形數（`renderer.info`），兩檔各一份 JSON，存到 `docs/visual/visual-quality/perf/`。
- 這台開發機是 RTX 5080，量不到內顯。中檔是現況，不設新預算，只記錄基準，並請使用者若有內顯筆電時讀一次面板上的 fps，確認「中檔 30 fps」；沒有就標為「未在內顯真機驗證」。
- 高檔預算：在 5080、1080p 上 GPU p50 ≤ 8 ms（含車載相機）。推導：中階獨顯（約 RTX 3060 等級）以約 3 倍慢估計（估計值，非量測），仍能在 60 fps 的 16.7 ms 內完成 GPU 工作並留餘裕給 CPU。
- 每個高檔 PR 附基準 JSON，改前改後並列；中檔數字必須不變（容許量測雜訊 ±5%）。

## 5. 高檔的質感子項目

每項一個 issue、一個 PR，只動高檔路徑。

### A 地面與路邊

- 人行道：pavement 貼圖、路緣石（帶倒角的擠出幾何，與道路合併繪製）。
- 路肩過渡：草帶與碎石路肩，以地形 shader 依離道路距離混合。
- 地形：多層混合加上大尺度變化（乾草、綠草、岩石、沙），坡度高處露岩，法線貼圖。
- 近景草叢與地面散落物（instancing）。

### B 光影

- 接觸陰影貼片（車、樹、建築底部的暗圈）；暗度受色塊遮罩測試約束。
- 陰影貼圖解析度與柔邊提高；依時段變化的陰影強度；遠景空氣透視（霧色隨太陽方向偏暖／偏冷）。
- 主畫面加 SSAO（半解析度）與調色微調；車載畫面不經過後製。

### C 植被與小物件

- 樹幹改為彎曲的放樣曲面並貼 bark；樹冠多層、葉片帶 alpha 貼圖與法線偏移，同種合併成 instancing。
- 葡萄園改為一行一行的植株加支架；丘陵加灌木叢（遠景低面數 instancing）。
- 路燈、節慶帳篷、旗子重新建模（帳篷帶布料皺褶與條紋，旗子在 vertex shader 中隨風擺動）。
- 高檔路徑的 draw call 合併（第 4 期延後的工作，只在高檔做）。

### D 車子

- 烤漆用 `daylight.hdr` 的環境反射與 clearcoat、車身接縫線（法線貼圖或細溝幾何）、輪拱暗面、接地陰影貼片。
- 交通車同樣細化；低面數車內裝（座椅、方向盤）。
- 兩檔都維持 `2026-10-01` spec 5.1 對打包檔的介面承諾（外框尺寸、輪子節點、`Glass` 材質名、每台車幾何獨立）。

## 6. 測試與驗收

- **node harness**（沿用 `tests/test_world_render.py` 的假 kit 做法）：
  - **中檔不變**：`quality="medium"` 時各 builder 的輸出（物件數、幾何頂點數、材質參數、顏色）與改動前的快照相同。快照在第 0 項建立。
  - `?gfx=` 解析；`localStorage` 不可用時退回初選；GPU 名稱初選表。
  - 舊地圖下 `quality` 不改變任何東西（hook 回傳「不處理」）。
  - 高檔新顏色都在 `PALETTE` 並通過現有色塊遮罩測試。
  - 兩檔的工廠契約（車、人）都符合。
- **效能**：見 4.4。
- **Vision 回歸**：見 4.3；調參 seed 與驗收 seed 分開。
- **截圖**：每項附同一位置的中／高並列，以及同一時刻兩檔的車載相機畫面，放 `docs/visual/visual-quality/`。
- 瀏覽器測試用 chrome-cdp-ex（背景模式，`CDP_PORT=9222`），同時只開一個 jevpilot 分頁。
- 既有 Python 測試全部通過。

## 7. 實作順序

0 畫質切換、中檔快照、效能量測 → A 地面與路邊 → B 光影 → C 植被與小物件 → D 車子。每項都從 main 開分支，先在 issue 留 brief，TDD，發 PR 前跑 pre-submit review。

## 8. 風險

- **效能替代指標不準**：5080 與內顯、中階獨顯的倍數都是估計；有真機讀數時校正，校正前相關說法都標為估計。
- **兩套世界的維護成本**：中、高兩條路徑並存；以中檔快照測試鎖住中檔，避免高檔的改動外溢。
- **Vision 分布改變**：高檔車載畫面不同，RT-DETR 與色相讀燈可能受影響；以驗收 seed 量化，不以少數幾趟下結論。
- **打包檔**：若切換重建或像素比需要打包檔補丁，照 `BUNDLE_PATCHES.md` 流程登記並調 `?v=`。
