# Solmare Coast 畫面質感與畫質分級

日期：2026-10-03。前置：`2026-10-01-solmare-coast-design.md`（第 1–4 期已合併，本案取代其第 5 期的「效能調校」部分）。

## 1. 目標與成功標準

- 畫面明顯不再陽春：地面與路邊、光影、植被與小物件、車子四塊各自以改前／改後截圖驗收。
- 畫質分級 **低／中／高** 三檔，像遊戲一樣可切換；中檔在 1080p 內顯筆電上 ≥ 30 fps。
- Vision 的閉環結果不因畫面改動而退步，也不因使用者選的畫質而改變。
- 舊地圖（Skyline City、Small town、Interstate 08）與 `lap=1` 的行為和分數不變；所有改動只在 `world.type === "coast"` 下生效。

## 2. 範圍

做：畫質分級與效能量測（第 0 項），以及 A 地面與路邊、B 光影、C 植被與小物件、D 車子。

不做：
- 逐項自訂的畫面設定、「極高」檔、「自訂」檔（使用者選定只要低／中／高）。
- 交通與行人密度（#22 照原 issue 做，不併入）。
- 號誌的燈色、燈形、號誌頭數量（AGENTS.md：不為感知改世界；#30 撤回既有改動）。
- 地圖路網與版圖。

## 3. 現況（2026-10-03 讀碼與截圖）

- 沒有畫質設定；`post.js`（HDR + bloom + 調色）在所有設備上全開，陰影相機半寬 130 m（`sky.js` 的 `SHADOW_HALF`）。
- 沒有主畫面 fps 量測；右下角的 FPS 是車載相機小窗的更新率（`semif-layer.js` 的 `pipFpsText`）。
- 車載相機用同一顆 renderer、同一個 scene 畫進自己的 render target（`semif-layer.js` 約 1233 行），所以它看得到所有物件與共用的陰影貼圖，但不經過 `post.js`。
- 截圖（`docs/visual/new-ui/after-engaged.jpg`）上最陽春的地方：人行道整片無紋理白色且無路緣石；路外是均勻土黃；丘陵光禿；棕櫚是直圓柱加平板葉；葡萄園像綠色方塊；帳篷是純白錐體；路燈粗大；車子缺反射、接縫與接地陰影；整體缺環境遮蔽，物件浮在地上。
- 已有的 CC0 貼圖（`web/textures/`）：asphalt、pavement、grass、dry、sand、rock、bark、brick、`daylight.hdr`。

## 4. 畫質分級（第 0 項）

### 4.1 Vision 不隨畫質變動

主畫面與車載相機共用 scene。為了讓 Vision 在任何設備、任何畫質下看到同一個世界：

- **基礎世界**（three.js layer 0）在三檔完全相同：道路、地形、建築、號誌、車、人、樹的主體。車載相機只渲染 layer 0。
- **主畫面限定細節**放在 layer 1（例如加密的草叢、遠景灌木、地面散落物、車內裝），只有主畫面相機啟用 layer 1；畫質檔只增減 layer 1 的內容。
- **全螢幕效果**（後製、SSAO）只在 `post.js` 的主畫面路徑裡。
- **陰影貼圖**是共用的，解析度隨畫質變；它對車載畫面的影響只有陰影邊緣的柔度。閉環評估一律以 `?gfx=medium` 固定畫質，讓評估彼此可比；這個邊界寫進 PR 與 README。

### 4.2 三檔內容

| 項目 | 低 | 中 | 高 |
|---|---|---|---|
| 渲染像素比 | 0.75 × 原生，上限 1 | 原生，上限 1.25 | 原生，上限 2 |
| 後製 | 只做色調映射與調色（不開 bloom） | 調色 + bloom（半解析度一層） | 調色 + 三層 bloom（現況） |
| SSAO | 關 | 關 | 開（半解析度） |
| 陰影貼圖／半寬 | 1024／70 m | 2048／100 m | 4096／130 m（現況） |
| layer 1 細節 | 無 | 近景 | 近景＋遠景 |
| 霧與遠景剔除 | 近 | 中 | 遠 |
| 貼圖非等向過濾 | 1 | 4 | 8 |

車載相機的解析度、物件、貼圖不受影響（4.1）。陰影半寬下限 70 m 涵蓋車載相機的 75 m 讀取距離的大部分；落在範圍外的物件沒有陰影，三檔對車載相機都一樣處理（同一塊範圍內的陰影一定存在）。

### 4.3 選擇與切換

- 第一次開啟：依 `WEBGL_debug_renderer_info` 的 GPU 名稱初選（含 Intel／UHD／Iris／Adreno／Mali／Apple GPU 等字樣 → 低或中），再實測約 3 秒的每幀時間校正一次。
- 執行中：主畫面 fps 連續 5 秒低於 27 時降一檔，提示一次「畫質已調為 中」。使用者手動選過之後，不再自動降檔。
- 設定存在 `localStorage`（讀寫包 try/catch，失敗就用初選）；網址參數 `?gfx=low|medium|high` 優先，供截圖與評估重現。
- 入口：底部控制列的齒輪圖示，開一個 Solmare 風格的小面板（三個選項＋一行說明每檔差別），可用鍵盤操作；面板內有「顯示 FPS」開關，顯示主畫面 fps 與 GPU 毫秒。
- 像素比、後製、SSAO、陰影、過濾即時生效；layer 1 細節重建時顯示「套用中」。

### 4.4 效能量測

- 新增主畫面的每幀時間量測；有 `EXT_disjoint_timer_query_webgl2` 時同時量 GPU 時間。
- 基準跑法：固定 seed 與起點（Solmare Festival），1920×1080，自駕 60 秒，記錄 p50／p5 fps、GPU 毫秒 p50、draw call 與三角形數（`renderer.info`）。結果寫成 JSON 存到 `docs/visual/visual-quality/perf/`。
- 這台開發機是 RTX 5080，量不到內顯。替代預算：**中檔 GPU 時間 p50 ≤ 3 ms（1080p，在 5080 上量）**。推導：Iris Xe 等級內顯以約 10 倍慢估計（估計值，非量測），30 fps 的 33 ms 中留一半給 CPU、模擬與車載相機。使用者若能提供內顯筆電，第 0 項完成時與第 D 項完成時各請使用者讀一次面板上的 fps，用來校正這個 10 倍；沒有就在 PR 註明「未在內顯真機驗證」。
- draw call 上限在第 0 項量完現況後訂定，寫回本 spec。

## 5. 質感子項目

每項一個 issue、一個 PR。新效果必須掛在某一檔之下；中檔的成本以 4.4 的預算為準。

### A 地面與路邊

- 人行道：pavement 貼圖、路緣石（帶倒角的擠出幾何，與道路合併繪製）。
- 路肩過渡：草帶與碎石路肩，以地形 shader 依離道路距離混合，不加幾何。
- 地形：多層混合加上大尺度變化（乾草、綠草、岩石、沙），丘陵坡度高處露岩。
- layer 1：近景草叢與地面散落物（instancing），中檔只有近景。

### B 光影

- 高檔 SSAO；中低檔以烘焙的接觸陰影貼片（車、樹、建築底部的暗圈，layer 0 內的便宜幾何）取代。
- 陰影柔邊與依時段變化的陰影強度；遠景加強空氣透視（霧色隨太陽方向偏暖／偏冷）。
- 主畫面調色微調；車載畫面不經過後製，不受影響。

### C 植被與小物件

- 樹幹改為彎曲的放樣曲面並貼 bark；樹冠多層、葉片帶 alpha 貼圖與法線偏移，同種合併成 instancing。
- 葡萄園改為一行一行的植株加支架；丘陵加灌木叢（layer 1 遠景）。
- 路燈、節慶帳篷、旗子重新建模（帳篷帶布料皺褶與條紋，旗子隨風擺動在 vertex shader 中做）。
- 第 4 期延後的 draw call 合併在這一項完成。

### D 車子

- 烤漆用 `daylight.hdr` 的環境反射與 clearcoat、車身接縫線（法線貼圖或細溝幾何）、輪拱暗面、接地陰影貼片。
- 交通車同樣細化；車內裝（座椅、方向盤）只在 layer 1。
- 維持 `2026-10-01` spec 5.1 對打包檔的介面承諾（外框尺寸、輪子節點、`Glass` 材質名、每台車幾何獨立）。

## 6. 測試與驗收

- **node harness**（沿用 `tests/test_world_render.py` 的假 kit 做法）：
  - 三檔設定表的內容與 4.2 一致；`?gfx=` 解析；`localStorage` 不可用時退回初選。
  - 車載相機只開 layer 0；layer 1 物件不出現在車載相機的 render 清單。
  - 舊地圖下畫質設定不改變任何東西（hook 回傳「不處理」）。
  - 新顏色都在 `PALETTE` 並通過現有色塊遮罩測試。
  - 工廠契約（車、人）照舊。
- **效能**：每個 PR 附 4.4 的基準 JSON，改前改後並列；中檔 GPU p50 增加不超過 10% 或仍在 3 ms 內，低檔不得變慢。
- **Vision 回歸**：A、C、D 用 #28 的閉環評估工具，以驗收 seed、`?gfx=medium` 跑改前改後，並列回報發生率（例如「闖紅燈 x/30、追撞 y/30」）；調參 seed 與驗收 seed 分開。退步就修感知，不改回世界的質感。B 只動主畫面，附一張車載畫面改前改後的逐像素比對說明沒有改到。
- **截圖**：每項附改前／改後，三檔各一張，放 `docs/visual/visual-quality/`。
- 瀏覽器測試用 chrome-cdp-ex（背景模式，`CDP_PORT=9222`），同時只開一個 jevpilot 分頁。
- 既有 Python 測試全部通過。

## 7. 實作順序

0 畫質分級與效能量測 → A 地面與路邊 → B 光影 → C 植被與小物件 → D 車子。每項都從 main 開分支，先在 issue 留 brief，TDD，發 PR 前跑 pre-submit review。

## 8. 風險

- **效能替代指標不準**：5080 對內顯的 10 倍是估計；以真機讀數校正，校正前所有「中檔 30 fps」的說法都標為估計。
- **Vision 分布改變**：A、C、D 會改變車載畫面；RT-DETR 與色相讀燈可能受影響。以驗收 seed 量化，不以少數幾趟下結論。
- **layer 機制與打包檔**：打包檔的相機與 render 流程沒有原始碼；若主畫面相機的 layer 設定需要補丁，照 `BUNDLE_PATCHES.md` 流程登記並調 `?v=`。
- **自動降檔來回跳**：只降不升，手動選過就停。
